NarrativeFlow: Flow-Based Vision-Language-Action Model Using Robot Velocity Fields

Card 02 论文概述

论文概述

  • 聚焦语言条件流式机器人操作任务，解决现有方法将机器人流粗略近似为稀疏关键点位移、无法适配语言条件、模型中间表示易受背景/光照等无关视觉细节干扰的核心问题
  • 提出NarrativeFlow方法，在流匹配框架下将机器人流建模为连续速度场，引入辅助监督信号引导模型捕捉任务相关场景变化，实现高质量语言条件机器人流生成
  • 通过标准数据集测试和真实机器人实验验证方法有效性，提升跨机器人平台的泛化操作能力
Card 03 核心贡献

核心贡献

  • 提出NarrativeFlow，基于流匹配框架将机器人流建模为概率速度场，实现高质量语言条件机器人流生成，解决现有方法流表示粗糙、不支持语言条件的问题
  • 设计Narrative Delta损失作为辅助训练目标，对齐模型中间表示与任务相关场景变化的叙事表示，同时引入专用子任务token缓解流生成主目标与辅助目标的学习信号干扰
  • 在Fractal、Bridge V2标准语言条件操作数据集上验证，NarrativeFlow在平均位移误差、最终位移误差等指标上显著优于代表性基线方法
  • 通过真实移动机器人实验证明，NarrativeFlow在移动抽屉关闭、移动分拣、移动杯子堆叠三类任务上的成功率高于基线方法，与真值流条件的性能差距更小
Card 04 方法描述

方法描述

  • 整体架构包含视觉-语言融合编码器和Flow-as-Flow模块两部分：输入为自然语言指令和初始图像，分别用Qwen3-Embedding-0.6B和DINOv3-ViT-B/16提取语言和视觉特征
  • 创新点1：视觉-语言融合编码器引入两个专用子任务token，分别服务于流生成条件提供和Narrative Delta损失计算，避免单token导致的多目标学习信号纠缠，提升特征表示的专一性
  • 创新点2：设计Narrative Delta辅助损失，离线用多模态大模型生成描述任务相关场景变化的多个文本描述，嵌入后得到叙事表示，通过余弦相似度对齐对应子任务token的输出，引导模型忽略任务无关视觉细节，聚焦关键场景变化
  • 创新点3：Flow-as-Flow模块基于Diffusion Transformer（DiT）架构实现，将初始图像、语言条件、时间步作为条件输入，通过流匹配框架预测连续速度场，推理时通过积分速度场生成全时间步的机器人流
Card 05 数据集与资源

数据集与资源

  • 使用的数据集：Fractal（Google Robot平台采集，共87212个样本，平均帧率3fps，平均时长14.15s）和Bridge V2（WidowX平台采集，共60064个样本，平均帧率5fps，平均时长7.51s）两个标准跨平台真实机器人操作数据集
  • 模型规模：约487M可训练参数
  • 训练资源：使用GeForce RTX 5090 32GB GPU训练，总训练时间约6小时，单样本推理时间约62ms
  • 辅助工具：使用CoTracker3提取机器人流ground truth，使用微调后的Robot-SAM提取末端执行器分割掩码，使用Qwen3.5-9B生成Narrative Delta损失所需的场景变化文本描述
Card 06 评估与结果

评估与结果

  • 评估环境与基准：标准数据集测试对比基线FLIP、Im2Flow2Act；真实机器人实验使用丰田Human Support Robot（HSR）11自由度移动机器人，评估移动抽屉关闭、移动分拣、移动杯子堆叠三类任务
  • 主要评估指标：平均位移误差（ADE，越低越好，主指标）、最终位移误差（FDE，越低越好）、小于delta比例（LTDR，越高越好），真实实验额外采用任务成功率作为指标
  • 关键实验结果：

- 标准数据集测试：NarrativeFlow在Fractal上ADE达21.68，优于最优基线15.46点；在Bridge V2上ADE达30.59，优于最优基线20.14点，所有指标提升均具有统计显著性（p<0.01）

- 消融实验验证：移除子任务token或Narrative Delta损失均会导致性能下降，证明两个设计的有效性

- 真实机器人实验：NarrativeFlow平均成功率达55%，高于Im2Flow2Act的42%和FLIP的28%，与真值流条件的oracle方法性能差距仅8个百分点，远小于基线的21个百分点
