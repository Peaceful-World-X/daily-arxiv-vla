Card 02 论文概述

论文概述

  • 论文研究了 Vision-Language-Action (VLA) 模型中训练-free token skipping 方法在闭环机器人控制中的可靠性问题，发现当前方法存在静默失败（silent failure）风险
  • 当门控信号（gate）从之前的加速前向传播中自收获（self-harvested）时，被跳过的 token 无法提供更新信息，导致门控产生盲区，失败信号在控制步骤间累积，且这种累积无法被现有动作级检测器发现
  • 提出了 actuation-slack refresh 方法：利用机器人执行动作时的空闲时间窗口（actuation slack，约 400ms）运行一次 dense pass，为下一步提供干净的门控信号和 KV 缓存，从而不增加关键路径延迟
Card 03 核心贡献

核心贡献

  • 隔离实验设计：通过控制变量实验（固定门控选择规则和 skip ratio，仅改变门控信号来源），证明决定闭环可靠性的关键因素是门控信号的来源（provenance）而非跳过机制本身（reuse vs deletion）
  • 提出 Actuation-Slack Refresh：一种无触发器的无条件刷新机制，在动作执行间隙运行 dense pass，为下一步提供 clean gate 和 fresh KV base，将 0.9 skip ratio 下的成功率从 0.68（reuse）和 0.31（deletion）恢复到 0.98
  • 解释现有方法失效原因：系统分析了 VLA-Cache、VLA-Pruner 和 SAFE-Pruner 的失败模式，揭示 SAFE-Pruner 的自收获触发机制在关键失败时刻几乎不触发（3 次 / 3,222 次编码），导致成功率仅 0.19
  • 广泛验证与部署：在 2 个 VLA 策略、4 个 LIBERO 套件、4 个 SIMPLER 任务以及真实 AgileX Piper 机械臂上验证了方法的有效性，服务延迟比 dense 低 18–22%
Card 04 方法描述

方法描述

  • 两种 Token Skipping 机制：reuse（复用缓存 KV，如 VLA-Cache）和 deletion（直接剪枝 token，如 VLA-Pruner），两者都依赖 gate 信号决定保留或跳过哪些 visual token
  • 核心概念 - Gate Provenance：区分 self-harvested gate（来自当前稀疏前向传播，信号已过期）和 clean gate（来自完整 dense pass，信号准确）
  • Actuation-Slack Refresh 机制：

- 利用 VLA 策略的 chunked 执行特性：每个 chunk 包含 K=8 个动作，执行需约 400ms，而前向传播仅需 ~63ms，留下大量空闲时间（actuation slack）

- 在执行当前 chunk 动作的同时，在 GPU 上运行一次 dense pass（丢弃其 action output），为下一步 t+1 生成 clean gate 和 fresh KV base

- 该 dense pass 在非关键路径（off critical path）上运行，不增加服务延迟

  • 无条件刷新设计：由于现有动作级检测器和基于自 harvested 一致性的触发器（如 SAFE-Pruner 的 κ_t）都无法可靠检测到 provenance-induced failure，因此采用无条件每块刷新而非触发式刷新

Card 06 评估与结果

评估与结果

  • 评估环境与基准：

- 仿真环境：LIBERO 和 SIMPLER 基准，使用 4 个 LIBERO 套件和 4 个 SIMPLER 任务

- 真实机器人：AgileX Piper 机械臂，3 个任务，每任务 40 集

- 对比基线：VLA-Cache（reuse）、VLA-Pruner（deletion）、SAFE-Pruner（triggered refresh）

  • 主要评估指标：Success Rate（任务成功率）、Serve Latency（关键路径服务延迟）
  • 关键实验结果：

- 闭环成功率：在 LIBERO-Object 上 skip ratio 0.9 时，self-harvested gate 导致 reuse 从 1.00 降至 0.68，deletion 降至 0.31；actuation-slack refresh 将 VLA-Cache 从 0.66 提升到 0.96，VLA-Pruner 从 0.98 维持到 0.98

- 延迟降低：在 H100 上，方法以 52.0 ms serving，比 dense（63.4 ms）快约 18%；在 RTX 4090 上以 97.0 ms serving，比 dense（123.3 ms）快约 21%；真实机器人上 serve latency 为 98.1 ms，比 dense（125.6 ms）降低 21.9%

- 触发机制失效：SAFE-Pruner 的触发器在 Object 上 3,222 次编码中仅触发 3 次（0.09%），成功率仅 0.19；而无条件 refresh 达到 0.98

- 边界分析：self-harvested gate 在 Object 上 skip ratio 超过 0.65 后开始显著下降，而 clean gate 在测试范围内（0.97）保持与 dense 无显著差异

- 刷新频率：每 2 块刷新一次可保持成功率 1.00，每 4 块降至 0.90，因此无条件每块刷新是最优选择

- 真实机器人验证：延迟排序（ours < VC < VP < dense）与仿真一致，验证了系统在实际部署中的可行性
