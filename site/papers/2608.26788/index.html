Card 02 论文概述

论文概述

  • 提出 Instruct-to-Act 框架，将具身智能体的决策过程解耦为规划（VLM Planner）和控制（World Model Controller）两个模块，前者生成高级自然语言指令，后者执行低级别实时动作
  • 解决预训练视觉-语言模型（VLM）难以直接生成高频率、低延迟动作序列的问题，同时弥补传统世界模型控制器缺乏开放式任务语言指导的不足
  • 通过事后指令标注（post-hoc instruction annotation）和行为克隆训练环境特定的轻量级控制器，使其能够执行任意预训练 VLM 规划器生成的自然语言指令
Card 03 核心贡献

核心贡献

  • 提出 plug-and-play 的规划-控制解耦范式，支持任意预训练 VLM 作为规划器而无需微调，仅需训练轻量级的环境特定控制器
  • 设计语言感知的世界模型控制器（基于 DreamerV3 风格的 RSSM），通过 VLM 对控制器自身策略 Rollout 进行事后指令标注，联合优化世界模型、Actor-Critic 和行为克隆损失
  • 实现异步在线推理机制，规划器与控制器并行执行，规划器可在后台持续推理的同时控制器实时执行动作，显著提升吞吐量
  • 将框架自然扩展到多智能体协作场景，支持去中心化/中心化的语言通信协调，无需专门的 MARL 训练
  • 在 7 个跨领域的具身环境（含 3 个多智能体环境）上验证，在 6/7 任务上达到有竞争力的性能
Card 04 方法描述

方法描述

  • Planner（规划器）：使用任意指令调优的 VLM（如 GPT-4o、Qwen-VL-2.5-72B、Gemma-3-27B、LLaVA-v1.6-34B），在推理时维护记忆库（memory bank）和部分计划（partial plan），根据观察历史和控制器的指令完成概率异步生成稀疏高级指令
  • Controller（控制器）：基于 RSSM（Recurrent State Space Model） 的 800M 参数世界模型，采用 CLIP-base-224 和 DINOv2-base 视觉特征，MiniLM-L6-H384-uncased 语言嵌入；包含额外的指令完成预测头（stop head），当无指令时使用学习的 null embedding 自主执行
  • 训练流程：控制器先在空语言条件下收集策略 Rollout 存入 FIFO 重放缓冲区（容量 1024），然后使用 GPT-4o 作为标注器对随机采样的时间段（长度 1-20）进行事后指令标注（标注 50% 的缓冲区数据），联合优化模型损失、价值损失、Actor 损失、行为克隆损失（L_BC）和停止预测损失（L_stop）
  • 多智能体推理：每个智能体共享控制器参数但维护独立的隐状态，规划器通过共享聊天室（Chatroom）进行去中心化或中心化的语言通信，协调子目标和角色分配
Card 05 数据集与资源

数据集与资源

  • 评估环境：Atari（Arcade Learning Environment）、MineRL ObtainDiamond（Minecraft 钻石任务）、Crafter、DeepMind Lab（explore_goal_locations）、Overcooked-AI、Pico Park（2-8 玩家合作平台解谜）、MindCraft（Minecraft 多智能体协作）
  • 模型规模：Controller 主要使用 800M 参数 RSSM（另有 50M/200M 变体）；Planner 使用不同规模的 VLM（从 2B 到 72B 参数不等）
  • 训练资源：每个环境训练约 23 GPU-hours（4 RTX A6000 GPUs），约 5.5M 环境步；VLM 事后标注增加约 17% GPU-hours 和 12% 训练开销
Card 06 评估与结果

评估与结果

  • 评估环境：100 个 episode（无探索噪声，ε=0，温度 τ=0.8），遵循各环境官方协议（Atari sticky actions/no-op starts、MineRL 标准协议等）
  • 主要指标：Atari 分数、Minecraft Diamond 完成率、Crafter 成就数、DMLab 目标位置探索、Overcooked 奖励、Pico Park 通关率、MindCraft 成功率；指令遵循准确率（instruction-following accuracy）
  • 关键实验结果：

- 平均指令遵循准确率达 92.8%，跨不同 VLM 规划器稳定性高（86%-97%）

- 在 7 个任务中的 6 个上性能具有竞争力，优于直接 VLM 动作生成和仅使用控制器的基线

- 异步在线规划比同步离线规划吞吐量快一个数量级，且在 Minecraft Diamond 上性能更高（GPT-4o：10.75 vs 9.60）

- 多智能体去中心化通信在 Pico Park 上优于中心化方案，且保持相当吞吐量

- 跨规划器迁移稳定（训练/评估交叉矩阵 9.2-10.2 分），表明控制器不过度拟合特定规划器的措辞

- 控制器架构不限于 RSSM，Transformer 世界模型也能达到相近性能（11.2 vs 11.0）
