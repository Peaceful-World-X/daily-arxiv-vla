Card 02 论文概述

论文概述

  • 论文提出了 DroneCATS-Agent，一种将多模态大语言模型（MLLM）直接嵌入无人机控制环路的通用架构，其动作空间完全通过提示词声明，无需微调或函数调用模式
  • 构建了 DroneCATS 基准，从接近、跟踪、搜索和指挥四个维度系统评估 MLLM 作为视觉-语言-动作代理的能力，并特别关注模型作为独立变量的表现
  • 研究发现，小模型在导航能力上接近甚至超越前沿模型，但失败主要源于无法正确使用“声明到达”这一终止动作，即协议遵守能力不足
Card 03 核心贡献

核心贡献

  • DroneCATS-Agent：一种模型无关的无人机代理，通过提示词声明四种动作（go、rotate、think、finished），使任何能读取提示的 MLLM 均可直接接入
  • 统一的闭环评估协议：采用基于模型自身“到达声明”的单一成功标准，覆盖接近、跟踪和搜索所有任务，避免因轨迹漂移通过目标区域而误判成功
  • 多维度基准测试：在 100 个仿真 episodes 上评估了 9 个模型（包括前沿 API 模型和开源小模型），涵盖单无人机四大任务和多无人机指挥场景
  • “声明发现”：揭示了小模型在导航能力足够的情况下，因过早或不发出到达声明而失败的核心瓶颈，将差距定位在协议遵守而非空间感知
Card 04 方法描述

方法描述

  • 代理架构采用 点选接口（go 动作）结合深度估计，模型通过输出像素坐标和深度值控制飞行，几何控制器负责将 2D 点反投影为 3D 位移，由飞控级联闭环执行
  • 新增 rotate 动作支持原地偏航搜索目标，think 动作允许悬停推理，finished 动作让模型自主声明到达，其中终止声明是模型的责任，由事后验证器判断是否成功
  • 所有动作仅通过自然语言提示词声明，模型输出 JSON 格式动作，无任何动作头或标记器，确保模型互换性；视觉输入仅限单目 RGB 图像，相机内参不提供给模型
  • 基准环境基于 AirSim 仿真器，采用住宅区和校园两张地图，任务设计通过目标是否移动、是否在初始画面内两个二元变量组合出四种任务类型，并统一使用 δ=5m 为成功半径
Card 05 数据集与资源

数据集与资源

  • DroneCATS Benchmark：包含 100 个仿真 episodes，分布于两个地图（住宅区和校园），其中单无人机任务 80 个（每类 20 个），多无人机（N=4）指挥任务 20 个
  • 评估模型：4 个前沿 API 模型（GPT-5、Claude Opus 5、Gemini 3.7 Flash、Gemini Robotics-ER 2），Qwen3.5 系列（2B/4B/9B/27B）和 Cosmos3-Edge-2B，共 9 个模型
  • 训练资源：不涉及模型训练，推理使用本地部署的 H100 GPU（2B/4B 模型）和 API 调用（更大模型），2B 模型需求约 10.5 GiB 显存，推理频率约 2 Hz
Card 06 评估与结果

评估与结果

  • 评估环境：AirSim 仿真器，无人机搭载单目 RGB 摄像头，控制频率约 2 Hz，episode 上限 300 秒
  • 主要指标：成功率（SR）（基于模型声明到达时距离 ≤5m 且目标可见）、预言成功率（OSR）（轨迹进入过目标区域）、导航误差（NE）、声明距离比等
  • 关键结果：Gemini 3.7 Flash 在单无人机接近任务中达到 65% 成功率，但搜索任务降至 40%；跟踪任务中该模型达到 80%，而 GPT-5 仅 15%；小模型 Qwen3.5-9B 在接近任务中虽进入目标区域比例高达 90%，但因声明过早成功率仅 35%；多无人机指挥中 Gemini 3.7 Flash 以 80% 成功率显著领先，而 GPT-5 仅 20%
  • 分析表明，小模型失败的核心是 协议遵守（声明太早或从不声明），而非导航能力，这一发现揭示了在边缘部署场景下模型需具备的持续协议遵守和正确终止能力
